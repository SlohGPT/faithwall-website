- **Side finding: NUL bytes in the prerendered HTML.** This is a React bug, not a branch fault. The built Lectio page holds 3 NUL bytes (one run of 1 and one run of 2), each sitting right before an em dash. The source JSON has none. The cause is React 18.3.1's `writeStringChunk` in `react-dom-server.node`. When a string won't fit in the 2048-byte output view, it flushes the whole view (`writeToDestination(destination, currentView)`) instead of only the bytes it wrote. If a 3-byte character such as "—" lands in the last 1 or 2 bytes, those bytes go out as zeros. It depends on position, so any text edit can move it onto or off a page. Two live pages already had it before this merge: `/blog/faithwall-vs-pray-com` (2) and `/blog/free-christian-apps-iphone-comparison` (2). The p57 edit moved an em dash onto a boundary, so the Lectio page now has 3 as well. HTML parsers drop a NUL in body text, so readers don't see anything. Still, it's malformed output on three public pages, and any edit can spread it.
- **Liveness is fine.** The bot produced work today.
